# 设计：主页直播入口与选集整理模型

## 设计目标

本设计希望把下面四个问题统一处理：

1. 主页直播按钮缺少全局显示开关。
2. 详情页选集列表不适合浏览长剧和多版本资源。
3. 选集标题识别过于粗糙，导致排序和倒序行为不稳定。
4. 选集重复与多版本混杂，影响浏览与续播。

核心思路不是继续追加局部判断，而是引入一层稳定的“选集整理模型”。

## 当前实现概览

```text
vod_play_from / vod_play_url
  -> Vod.setFlags()
  -> Flag.setEpisodes()
  -> Episode(name, desc, url, number)
  -> VideoActivity.setEpisodeAdapter()
  -> History.findEpisode() 按名称近似匹配
```

当前问题主要来自三个事实：

1. `Episode` 只保存极少字段，表达能力不足。
2. `Episode.equals()` 主要按名称判等，去重粒度过粗。
3. 排序、倒序、分页、历史定位都直接建立在当前扁平列表上。

## 设计原则

1. 保留原始标题与原始顺序，任何整理都必须可回退。
2. 结构化识别服务于展示，而不是替代原始数据。
3. 去重不能简单按名称或 URL 二选一，需要区分“同一集多版本”和“真正重复”。
4. 倒序应只作用于“主序号序列”，不能破坏分组和版本归类。
5. 手机端与电视端可有不同交互，但应共享同一套整理结果。
6. 剧集类正片优先显示简化后的纯序号，避免重复展示“第N集”。
7. 对同一语义的控制入口尽量单一化，避免正序/倒序出现重复按钮。

## 一、主页直播入口

### 当前状态

主页直播入口显示条件主要由 `LiveConfig.hasUrl()` 决定：

1. 手机端底部导航按是否存在直播配置决定是否显示。
2. 电视端首页功能区按是否存在直播配置决定是否显示。

### 实施方案

新增全局设置布尔值 `Setting.isHomeLiveVisible()`，**默认值为 `true`（开启）**。

显示公式为：

```text
showLiveEntry = LiveConfig.hasUrl() && Setting.isHomeLiveVisible()
```

用户可在设置页手动关闭该开关，关闭后手机端和电视端首页同步隐藏直播入口。

### 原因

1. 用户可能保留直播配置，但不希望首页露出直播入口。
2. 默认开启符合”开箱即用”原则，用户有配置即可见。
3. 该开关适合放在设置页，并可同时作用于手机端与电视端。
4. 不影响直播配置加载、本地直播导入、开机进入直播等已有逻辑。

## 二、选集整理模型

### 当前问题

目前 `Episode` 主要只有：

1. `name`
2. `desc`
3. `url`
4. `number`

其中 `number` 通过提取标题中的单个数字得到。这对于下面的标题明显不够：

1. `S02E03`
2. `第2季 第3集`
3. `电影版`
4. `OVA 01`
5. `第12集 1080P`
6. `第12集 国语`
7. `第12集 HDR`

### 建议引入的整理视图

可以不立即扩展持久化字段，但在详情解析后生成一层内存态的整理结果。

建议概念如下：

```text
EpisodeRaw
  原始 name / desc / url / 原始顺序

EpisodeMeta
  主序号
  季信息
  集信息
  内容类型
  版本标签
  格式标签
  语言标签
  排序键
  去重键
  展示键

EpisodeGroup
  分组名称
  分组类型
  episodes[]
```

### 建议识别维度

#### 1. 主序号

用于正序 / 倒序的主体。

候选来源：

1. `第X集 / 第X话 / EPX / EX`
2. `第X部`
3. `SxxExx`
4. 回退到原始顺序索引

#### 2. 内容类型

用于把正片和特别内容分开。

建议至少识别：

1. 正片
2. 预告
3. 花絮
4. 彩蛋
5. 特别篇
6. OVA / OAD / SP
7. 电影版 / 剧场版

#### 3. 版本标签

用于表示同一集的不同可选版本，而不是把它们误去重。

建议识别：

1. 清晰度，如 `4K`、`2160P`、`1080P`、`720P`
2. 视频编码，如 `H264`、`H265`、`HEVC`、`AV1`
3. 容器格式，如 `MP4`、`MKV`、`M3U8`
4. 语言或配音，如 `国语`、`粤语`、`原声`
5. 来源特征，如 `蓝光`、`WEB-DL`、`HDR`

### 展示名称规则

结构化后应区分“内部识别名”和“界面展示名”。

#### 1. 剧集类正片

当满足以下条件时，展示名默认简化为纯序号：

1. 已识别为剧集类正片。
2. 已识别出可信的主序号。
3. 不依赖额外文字来区分不同内容。

示例：

```text
原始标题：第1集
展示标题：1

原始标题：第12集
展示标题：12
```

#### 2. 非正片或非剧集内容

继续保留有辨识度的文本，例如：

1. 预告
2. 花絮
3. OVA 01
4. 剧场版
5. SP

#### 3. 同一集多版本

主集项保持纯序号，版本差异放在二级展示中，不混入主标题。

### 选集按钮展示层级

在现有“主标题 + 副标题 + 标签”的基础上，进一步明确为两级信息：

#### 1. 一级信息

一级信息用于决定按钮的主体尺寸与点击识别，应优先包含：

1. 集数
2. 副标题

其中：

1. 集数是一级主信息，必须稳定可见。
2. 副标题是一级补充信息，用于区分“终章 / 上 / 下 / 特别篇标题”等内容。
3. 当副标题缺失时，不应使用二级标签冒充副标题。

#### 2. 二级信息

二级信息用于补充同一集不同版本的差异，建议从标题中结构化提取以下标签：

1. 清晰度，如 `4K`、`2160P`、`1080P`、`720P`
2. 画质/来源，如 `HDR`、`蓝光`、`WEB-DL`
3. 格式/封装，如 `MKV`、`MP4`、`M3U8`
4. 视频大小，如 `1.8GB`
5. 语言/字幕，如 `国语`、`粤语`、`原声`、`中字`

#### 3. 展示规则

1. 当某一组内所有选集都只有集数信息时，按钮只显示单行。
2. 单行展示时，集数文字必须居中显示，避免出现左对齐造成的视觉偏移。
3. 当任一选集存在副标题时，该组按钮统一采用双行主区域。
4. 双行模式下，没有副标题的按钮也应保留占位，以保持所有按钮高度一致。
5. 二级信息不应挤占一级信息的主宽度计算，应作为补充标签区域展示。

### 排序策略

建议排序键由以下层次组成：

```text
内容类型优先级
  -> 季
  -> 主序号
  -> 版本优先级
  -> 原始顺序
```

其中：

1. 默认先显示正片，再显示特别篇、花絮、预告。
2. 正片内部按季和集排序。
3. 同一集下的多版本按版本优先级排列。
4. 解析失败时回退原始顺序，避免误判造成彻底错乱。

### 倒序策略

倒序不应直接对原始扁平数组做整体 `reverse()`。

建议调整为：

1. 先按分组得到有结构的结果。
2. 仅对当前展示分组中的主序号列表做反转。
3. 同一主序号下的版本顺序保持稳定。
4. 花絮、预告、电影版等不同类型分组不应被并入同一倒序逻辑。

这样可以避免“第12集 HDR”与“预告片”一起被粗暴翻转。

### 排序控制入口

当前详情页存在两个与正序/倒序相关的入口：

1. 带文字的按钮
2. 箭头式按钮

建议收敛为单一主入口：

1. 保留带文字的正序/倒序按钮。
2. 移除箭头式倒序按钮。
3. 文字按钮在状态切换后必须同步更新文本。

文案语义约定：

1. 文本表示当前状态，而不是下一步动作。
2. 当前为正序时显示“正序”。
3. 当前为倒序时显示“倒序”。

### 范围分页与定位

当前分页标题与分页跳转并没有建立在同一个稳定模型上，导致存在以下问题：

1. 范围标题与实际定位首集可能不一致。
2. 正序/倒序时的分页边界不够直观。
3. 手机端“更多选集”与电视端范围条难以共享同一套规则。

建议分页建立在“当前激活分组 + 当前排序方向”的基础上，而不是直接操作原始扁平列表。

建议为当前展示分组生成页对象：

```text
EpisodePage
  title       范围标题
  startIndex  当前展示列表中的起始索引
  endIndex    当前展示列表中的结束索引
  anchorIndex 范围切换后应定位到的首项索引
```

其中：

1. `title` 用于显示 `1~20`、`21~24`、`24~21`、`20~1` 等范围文案。
2. `anchorIndex` 必须与当前排序后的列表保持一致。
3. 范围切换时，始终定位到该范围内的第一个按钮。

分页规则建议明确为：

1. 正片分组默认每页 20 集。
2. 其他分组默认每页 10 个。
3. 正序分页按自然顺序切块，如 24 集时为 `1~20`、`21~24`。
4. 倒序分页按倒序后的自然顺序切块，如 24 集时为 `24~21`、`20~1`。
5. 分页标题与分页定位必须由同一套页对象生成，禁止标题和跳转分别计算。

## 三、去重与归类

### 当前问题

当前去重存在两个偏差：

1. 同名即视为同一集，容易吞掉不同版本。
2. 同一线路的动态补全会继续向原列表合并，噪音逐渐放大。

### 建议区分三种情况

#### 1. 真正重复

特征：

1. 主序号一致
2. 标题规范化后一致
3. URL 或核心播放语义高度一致
4. 标签差异极小

处理：

1. 直接去重

#### 2. 同一集多版本

特征：

1. 主序号一致
2. 内容类型一致
3. 版本标签不同

处理：

1. 归并到同一集下
2. 展示为质量 / 版本候选，而不是多个散落的集数按钮

#### 3. 名称近似但内容不同

特征：

1. 标题都含相似数字
2. 实际属于预告、花絮、SP、电影版等不同内容类型

处理：

1. 保持独立分组
2. 不参与正片集合并

### 建议的去重键

不建议继续使用“仅名称”。

建议至少基于：

```text
内容类型 + 季 + 主序号 + 规范化标题主体 + 版本标签摘要
```

URL 可以作为辅助，不应单独作为唯一依据。

## 四、UI 组织建议

### 手机端

当前手机端详情页以内联单行横向列表为主，“更多”再打开分页网格。

实施方向：

1. 默认即展示横向流动网格，而不是单行滚动。
2. 在选集标题区加入轻量分组切换。
3. 当存在多版本时，优先通过折叠归类与版本标签降低噪音，不再让不同版本无序挤占主集数序列。
4. 如果分组很多，可保留“更多”作为补充入口，但不再承担主要浏览职责。
5. 剧集类正片的网格项默认显示纯序号。
6. 主选集区继续保持网格展示，不回退为单行列表。
7. “更多选集”弹窗应尽量与主视图共享同一套分页与展示口径。

建议信息层次：

```text
线路
  -> 分组（正片 / 特别篇 / 预告 / 花絮）
    -> 横向流动网格
      -> 集内版本
```

### 电视端

电视端当前已有较强的焦点结构，因此建议保留“可遥控器操作优先”的前提。

实施方向：

1. 继续维持线路区、选集区、分页区的分层焦点逻辑。
2. 用分组条补充当前纯数字分页条，并让分组优先于分页。
3. 保留分页概念，但分页建立在分组后的主序号序列上。
4. 多版本切换尽量落在质量区或二级区，避免挤爆主选集横排。
5. 移除箭头式倒序按钮，仅保留文字状态按钮。
6. 视频页中的 `part` 组件不再作为默认可见区域，避免干扰选集主流程。

## 五、分页规则

分页尺寸不再使用单一固定值，而是按内容类型区分：

1. 剧集类正片按 20 集一组。
2. 其他内容按 10 个一组。

建议表达式：

```text
pageSize =
  if 内容为剧集类正片 then 20
  else 10
```

这样可以同时兼顾长剧浏览效率与非剧集内容的页签长度控制。

补充分页示例：

1. 24 集正序时应显示为 `1~20`、`21~24`。
2. 24 集倒序时应显示为 `24~21`、`20~1`。
3. 切换任一分页范围后，应定位到该范围内的第一个选集按钮。

## 六、视频页 Part 组件

### 当前状态

电视端详情页中的 `part` 组件本质上是按片名拆分关键词后的快捷搜索入口，并不属于选集系统。

### 决策

视频页面中的 `part` 组件可以不再显示。

### 原因

1. 它与“选集浏览 / 选集定位 / 多版本选择”不是同一层信息。
2. 会占用焦点路径与视觉空间，削弱选集区的主任务。
3. 在当前变更目标下，保留 `flag / quality / group / episode / range` 已足够覆盖主流程。

## 七、历史记录兼容

### 当前状态

历史定位依赖：

1. 线路名
2. 选集名称
3. 从名称中抽出的数字

这在标题变化、去重合并、版本整理后容易失效。

### 建议兼容策略

续播匹配按以下优先级尝试：

1. 旧的 `episodeUrl`
2. 结构化后的主序号与内容类型
3. 原始名称近似匹配
4. 当前分组首项

补充默认排序策略：

1. 已有观看历史的视频，选集默认倒序展示。
2. 尚未产生观看历史的视频，选集默认正序展示。

这样可以兼容历史库中已有记录，同时让新模型逐步接管。

## 八、分阶段落地建议

### 阶段 1：入口与数据探针

1. 增加主页直播入口开关。
2. 为选集标题解析增加调试性输出或内存态结构，观察典型站点命中率。

### 阶段 2：排序与去重

1. 先不大改 UI，只让现有列表消费新的排序结果。
2. 验证正片、特别篇、多版本的归类是否稳定。
3. 校验历史续播命中是否下降。
4. 验证剧集类正片能否稳定简化为纯序号展示。

### 阶段 3：UI 改造

1. 手机端切到横向流动网格。
2. 电视端调整分组条与分页逻辑。
3. 明确倒序仅作用于主序号序列。
4. 移除箭头式倒序按钮，仅保留文字状态按钮，并修正文案同步逻辑。

## 九、风险与缓解

### 风险 1：规则过拟合

缓解：

1. 保留原始顺序回退。
2. 结构化识别失败时不阻断播放。

### 风险 2：去重过度

缓解：

1. 明确区分“真正重复”和“同集多版本”。
2. 初期以保守归类优先，宁可少并，不要误合。

### 风险 3：历史定位丢失

缓解：

1. 多级回退匹配。
2. 在迁移期同时保留旧字段和新推导信息。

## 十、关键决策

| # | 决策 | 选择 | 放弃的备选方案 | 原因 |
|---|------|------|----------------|------|
| 1 | 主页直播入口默认值 | **默认开启**，由用户在设置中关闭 | 默认关闭由用户主动开启 | 有直播源即应可见，符合开箱即用原则；关闭是小众需求，不应拦截大多数用户 |
| 2 | 同一集多版本展示策略 | **折叠归类优先**，版本标签附着在选集项上 | 多版本平铺为独立按钮 | 主选集区噪音是核心痛点；折叠后仍可通过版本标签识别差异 |
| 3 | 分组优先级 | **正片优先**，特别篇/花絮/预告依次排后 | 按原始顺序混排 | 正片是大多数用户的核心诉求，应优先呈现 |
| 4 | 手机端”更多选集”入口 | **保留**为补充入口，主视图改为横向流动网格 | 完全移除”更多选集” | 网格作为主视图已满足日常浏览；保留入口兼容习惯操作 |
| 5 | 电视端分页与分组关系 | **分组优先于分页**：分组条优先获焦，分页条作用于当前分组内序列 | 继续纯数字分页，不引入分组条 | 纯分页在多类型内容下会将正片和特别篇混排，分组后分页才有意义 |
| 6 | 剧集类正片展示名 | **默认只显示纯序号**（如 `1`、`12`），去掉”第N集”前缀 | 保留原始标题展示 | 原始标题如”第12集”在列表中产生大量重复文字，纯序号更简洁易读 |
| 7 | 正序/倒序按钮入口 | **仅保留带文字的主按钮**，移除箭头式倒序按钮 | 同时保留两个入口 | 两个入口语义重叠，箭头式按钮对新用户缺乏可发现性 |
| 8 | 正序/倒序按钮文案 | **文本表示当前状态**（正序时显示”正序”，倒序时显示”倒序”） | 文本表示下一步动作（如”点击倒序”） | 状态文案对当前所处状态一目了然，与 Android 标准切换按钮惯例一致 |
| 9 | 分页尺寸 | **剧集类正片 20 集一组，其他内容 10 个一组** | 固定值（如全部 20 或全部 10） | 长剧正片用 20 减少翻页；花絮/预告数量少，10 个已足够且不让分页条过长 |
| 10 | 单行按钮对齐方式 | **只有集数时，主文本居中显示** | 保持默认左对齐 | 单一数字按钮左对齐会造成明显视觉偏移，居中更稳定 |
| 11 | 范围切换落点 | **切换范围后定位到该范围第一个选集** | 保留上一页中的相对偏移 | 页签的核心意义就是切换到新范围起点，保留偏移会增加认知负担 |
| 12 | 视频页 `part` 组件 | **默认不显示** | 继续保留为视频页一级组件 | 它属于快捷搜片，不属于选集主任务，保留会增加焦点噪音 |
