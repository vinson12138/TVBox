# 提案：重构 Leanback 首页布局与导航体验

## 背景

当前 `leanback` 风味首页已经具备数据源切换、功能入口、最近观看和推荐内容等基础能力，但整体信息组织仍偏向“纵向堆叠内容流”，存在以下持续性问题：

1. 首页缺少稳定的信息分区，用户需要在同一纵向列表中理解功能入口、最近观看和推荐内容。
2. 站点返回的分类信息已经存在，但首页没有直接消费，用户进入分类浏览前仍需额外跳转。
3. 顶部信息栏当前以标题为主，状态信息聚合度不足，不利于快速确认当前数据源、设置入口和联网状态。
4. 最近观看虽然已经出现在首页，但缺少“少量高频记录 + 更多入口”的明确层次。
5. 推荐内容当前主要作为扁平结果展示，无法直观区分剧集、动漫、电影、综艺等高频浏览方向。

这些问题在电视场景下会被进一步放大，因为用户依赖方向键浏览，任何额外的焦点跳转和信息混排，都会直接增加操作成本。

## 目标

本变更旨在把 `leanback` 首页重构为更直观、更低认知负担的双栏首页。

具体目标：

1. 将首页改造成“顶部状态栏 + 左侧导航栏 + 右侧内容区”的稳定结构。
2. 让左侧导航同时承载核心功能入口和站点返回的分类入口，减少不必要跳转。
3. 让顶部状态栏承担全局识别与快捷入口职责，并形成清晰的左右信息分布。
4. 让首页态下的右侧内容区聚焦高频内容，优先展示最近观看与四类最新推荐。
5. 保持现有数据源切换、收藏、搜索、分类浏览等核心能力可平滑迁移。

## 非目标

本提案不包含以下内容：

1. 不修改 Spider / JS / PY / JAR 插件协议。
2. 不调整 `mobile` 风味首页结构。
3. 不在本提案阶段确定所有卡片尺寸、动画、配色或像素级视觉细节。
4. 不直接复用现有 `HistoryDialog` 作为观看历史入口，除非后续设计阶段确认其职责需要扩展。
5. 不在当前提案中直接实施应用代码变更。

## 范围

### 包含范围

1. `leanback` 首页整体信息架构调整。
2. 顶部状态栏的内容组织与对齐规则。
3. 左侧导航栏的入口构成与排序原则。
4. 左侧导航项的常态、聚焦态、激活态三态规则。
5. 首页态下右侧内容区的推荐分层方式。
6. 分类态下右侧内容区的分页、筛选与滚动策略。
7. 搜索、收藏在首页右侧内容区中的承接方式。
8. 最近观看在首页中的展示数量与“更多历史”入口策略。

### 暂不纳入

1. 搜索页、收藏页、详情页、播放页的完整独立视觉重构。
2. 站点分类的命名标准化。
3. 联网状态的底层监控框架重写。

## 方案摘要

建议将 `leanback` 首页组织为如下结构：

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ 数据源名称                                                [设置] [网络] 时间  │
├────────────────┬──────────────────────────────────────────────────────────┤
│ 搜索           │ 最近观看：最多 4 条，附“更多历史”入口                          │
│ 首页           │                                                           │
│ 剧集           │ 最新剧集                                                   │
│ 动漫           │                                                           │
│ 电影           │ 最新动漫                                                   │
│ 综艺           │                                                           │
│ 其他站点分类…   │ 最新电影                                                    │
│ 收藏           │                                                           │
│                │ 最新综艺                                                  │
└────────────────┴──────────────────────────────────────────────────────────┘
```

### 顶部状态栏

1. 左侧保留当前数据源名称，承担“当前首页上下文”的主识别信息。
2. 右侧内容整体右对齐，包含设置图标、网络状态图标和时间。
3. 设置作为可聚焦快捷入口，网络和时间默认作为状态展示。

### 左侧导航栏

1. 固定保留高频入口：搜索、首页、收藏。
2. 首页下方承接站点返回的高频分类，优先包含剧集、动漫、电影、综艺。
3. 若站点返回更多分类，则继续向下承接，不丢失站点能力。

### 右侧内容区

当左侧选中“首页”时，右侧显示五条固定内容带：

1. 最近观看
2. 最新剧集
3. 最新动漫
4. 最新电影
5. 最新综艺

当左侧选中某个分类时，右侧切换为该分类的浏览内容，而不是继续维持首页仪表盘结构。

当左侧选中“搜索”或“收藏”时，右侧也应切换为对应内容面板，而不是再打开全屏页面。

## 已确认决策

1. 首页采用双栏布局，而不是继续沿用单一纵向内容流。
2. 顶部状态栏保留数据源信息，并将设置、网络、时间放在右侧。
3. 设置和网络优先使用图标表达，其中设置保留入口属性。
4. 首页态下右侧固定展示最近观看、最新剧集、最新动漫、最新电影、最新综艺。
5. 最近观看在首页最多展示 4 条，避免第一行超出屏幕宽度。
6. 首页左侧导航必须保留搜索、首页、收藏三个稳定入口。
7. 站点返回的分类应尽量直接进入首页左侧导航，而不是只在二级页面展示。
8. 左侧导航需要明确区分常态、聚焦态和激活态，避免焦点离开后仍被误认为“当前聚焦”。
9. 搜索和收藏在首页左栏中应与首页、分类采用一致的“选中即右栏切换”模型，而不是额外按确认后进入全屏页。
10. 分类态滚动到底时应继续加载下一页，筛选切换时仅重置分类内容区，不刷新整个右栏骨架。
11. 分类筛选按钮应具备常态、聚焦态、选中态三态表达，且允许“选中但当前未聚焦”的稳定呈现。

## 风险与待确认项

1. “最新剧集 / 动漫 / 电影 / 综艺”如何从不同站点分类中稳定映射，仍需后续设计阶段定义识别与回退规则。
2. 当前项目中的 `HistoryDialog` 主要承载配置历史，不等同于观看历史页；“更多历史”需要后续明确承接形态。
3. 右侧固定五条内容带会压缩单行高度，后续需要在设计阶段控制卡片尺寸和焦点密度。
4. 顶部状态栏右侧若同时引入多个可聚焦元素，需要进一步约束焦点路径，避免顶部导航过碎。
5. 搜索、收藏改为首页右栏承接后，需要控制其与现有独立页面能力之间的职责边界，避免出现两套长期分叉的交互模型。
