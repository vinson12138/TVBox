# 设计：Leanback 首页双栏重构

## 设计目标

本设计希望把 `leanback` 首页从“纵向内容流”重构为更稳定的电视端首页框架，统一解决以下问题：

1. 首页功能入口、最近观看、推荐内容混排，用户理解成本较高。
2. 站点返回的分类已存在，但首页没有直接承接，分类浏览路径偏长。
3. 顶部信息栏当前更像标题栏，而不是面向电视场景的全局状态栏。
4. 最近观看缺少明确的数量边界和“查看更多”承接。
5. 推荐内容没有按剧集、动漫、电影、综艺进行直观分层。

核心思路不是继续优化单个 Row，而是重建首页骨架，让首页在信息架构上先变得稳定。

## 当前实现概览

当前 `leanback` 首页主要由两部分组成：

```text
顶部 toolbar
  -> logo
  -> title（当前数据源，可左右切站点）
  -> clock

下方 VerticalGridView
  -> 功能入口 Row
  -> 最近观看 Row（按需插入）
  -> 推荐内容流
```

对应代码入口主要包括：

1. `app/src/leanback/java/com/fongmi/android/tv/ui/activity/HomeActivity.java`
2. `app/src/leanback/res/layout/activity_home.xml`
3. `app/src/leanback/java/com/fongmi/android/tv/ui/custom/CustomTitleView.java`

此外，站点分类入口已经存在于 `VodActivity` 的双区结构中：

```text
分类列表
  -> ViewPager 内容
```

这说明“站点分类作为首页左侧导航的一部分”与现有项目结构是兼容的，不需要从零创造新模型。

## 设计原则

1. 首页必须优先服务电视端方向键操作，而不是继续沿用内容流思维。
2. 首页态与分类浏览态应区分清楚，不把所有任务都塞进同一右侧区域。
3. 顶部状态栏优先承载全局识别和快捷入口，避免承担过多浏览功能。
4. 左侧导航应同时承载固定功能和站点分类，并保持排序稳定。
5. 首页右侧内容必须围绕高频任务组织，而不是直接平铺原始推荐结果。
6. 焦点路径必须可预测，避免顶部右侧出现过多可聚焦碎片。

## 一、总体布局

建议首页调整为如下结构：

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ 数据源名称                                                [设置] [网络] 时间 │
├────────────────┬──────────────────────────────────────────────────────────┤
│ 搜索           │ 最近观看：最多 4 条，附“更多历史”入口                    │
│ 首页           │                                                          │
│ 剧集           │ 最新剧集                                                 │
│ 动漫           │                                                          │
│ 电影           │ 最新动漫                                                 │
│ 综艺           │                                                          │
│ 其他站点分类…   │ 最新电影                                                 │
│ 收藏           │                                                          │
│                │ 最新综艺                                                 │
└────────────────┴──────────────────────────────────────────────────────────┘
```

### 分区职责

#### 1. 顶部状态栏

职责：

1. 告知当前首页上下文
2. 提供设置快捷入口
3. 展示联网状态
4. 展示时间

#### 2. 左侧导航栏

职责：

1. 提供稳定的首页级入口
2. 承接站点返回的分类
3. 决定右侧内容区当前处于“首页态”还是“分类态”
4. 在视觉上稳定表达“当前激活项”与“当前聚焦项”的区别

#### 3. 右侧内容区

职责：

1. 在首页态下作为“内容仪表盘”
2. 在分类态下作为“分类浏览区”

## 二、顶部状态栏

### 结构

状态栏采用“左文右图文”的布局：

```text
左侧：数据源名称
右侧：[设置图标] [网络图标] [时间]
```

### 对齐规则

1. 数据源名称左对齐。
2. 设置图标、网络图标、时间整体右对齐。
3. 时间位于最右侧，保持固定视觉锚点。

### 交互规则

1. 设置图标为可聚焦入口，可直接进入设置页。
2. 网络图标默认为状态展示，不强制要求可聚焦。
3. 时间仅作为状态展示，不参与焦点链。
4. 数据源名称可继续承担当前数据源标识；是否保留“左右切换站点”交互，由后续实现阶段结合焦点方案决定。

### 网络图标语义

建议仅表达轻量状态：

1. 已联网
2. 未联网
3. 有条件时区分 Wi-Fi / 有线

不建议在首页顶部展示复杂网络文字，以免破坏状态栏紧凑性。

## 三、左侧导航栏

### 固定入口

左侧导航中应固定保留以下入口：

1. 搜索
2. 首页
3. 收藏

### 分类入口

在固定入口之外，左侧导航承接站点返回的分类。默认优先关心以下高频分类：

1. 剧集
2. 动漫
3. 电影
4. 综艺

若站点返回更多分类，则继续向下承接，不丢弃站点原有能力。

### 排序建议

建议首页左栏采用以下顺序：

```text
搜索
首页
剧集
动漫
电影
综艺
其他站点分类…
收藏
```

原因：

1. 搜索和首页是全局高频入口，放在最前。
2. 剧集、动漫、电影、综艺构成首页的核心分类骨架。
3. 收藏保留在左栏中，但不打断内容分类的连续浏览节奏。

### 导航状态模型

左侧导航不应只依赖单一高亮样式，而应明确区分三种状态：

```text
常态
  当前未聚焦，且不是右侧正在承接的模式

聚焦态
  当前方向键真正停留在该导航项上

激活态
  焦点已离开左栏，但右侧内容区仍由该导航项决定
```

#### 导航三态规则

1. 当焦点停留在左栏项上时，导航项显示聚焦态。
2. 当焦点从左栏移动到顶部状态栏或右侧内容区时，左栏当前模式项切换为激活态，而不是继续表现为聚焦态。
3. 常态项不应与激活态混淆，避免用户误判当前右侧内容归属。
4. 聚焦态优先表达“当前方向键位置”，激活态优先表达“当前内容上下文”。
5. 搜索、首页、收藏、分类都遵循同一套三态规则，不做例外分支。

#### 导航触发模型

左栏导航建议统一采用“选中即切换右栏模式”的模型：

```text
左栏移动选中某项
  -> 更新该项为激活上下文
  -> 右栏切换到对应模式
  -> 用户右移进入该模式内容
```

含义：

1. 搜索、首页、收藏、分类都应在左栏选中时完成上下文切换。
2. 不再保留“某些项仅在按确认后才真正切换内容”的特殊行为。
3. 右移进入右栏时，进入的是已激活模式的内容首焦点，而不是先触发一次模式加载。

## 四、右侧内容区

### 0. 模式总览

右侧内容区建议明确为一个统一的模式容器，而不是只承载首页态与简化分类态。

```text
右侧模式
├─ HOME
├─ CATEGORY
├─ SEARCH
└─ KEEP
```

这样可以让左栏所有固定入口都遵循一致的“选中决定右栏内容”的交互逻辑。

### 1. 首页态

当左侧选中“首页”时，右侧显示五条固定内容带：

1. 最近观看
2. 最新剧集
3. 最新动漫
4. 最新电影
5. 最新综艺

这是首页的仪表盘态。

### 2. 分类态

当左侧选中某个分类时，右侧切换为该分类的浏览区，而不是继续展示五条固定内容带。

```text
左栏选中：首页
  -> 右侧显示首页仪表盘

左栏选中：剧集 / 动漫 / 电影 / 综艺 / 其他分类
  -> 右侧显示该分类的内容列表
```

#### 分类态分页策略

分类态采用“滚动到底自动加载下一页”的连续浏览模型，而不是“滚动到底重新刷新第一页”。

```text
进入分类
  -> 请求 page=1
  -> 渲染首屏内容
  -> 用户持续下滚
  -> 滚动到底
  -> 自动请求 page=2 / page=3 / ...
  -> 将新结果追加到现有内容尾部
```

具体规则：

1. 首次进入分类时，请求 `page=1`。
2. 右侧内容区滚动到底部时，自动请求下一页，不要求用户额外确认。
3. 新页结果必须以追加方式进入内容区，不能清空已加载内容。
4. 当返回结果为空，或站点返回的 `pageCount` 表示已到末页时，应停止继续加载。
5. 分页加载过程中，仅显示轻量追加加载态，不把整个右侧内容区切回全屏加载态。
6. 分类态分页应优先复用现有 `TypeFragment` / `CustomScroller` 的成熟模式，而不是重新发明一套滚动协议。

#### 分类态状态模型

为支撑分页追加，分类态不应只保留“当前一次请求结果”，而应维护一组稳定状态：

```text
CATEGORY 状态
├─ 当前分类 id
├─ 当前页 page
├─ 是否 loadingMore
├─ 是否 hasMore
├─ 当前筛选 extends
├─ 筛选区是否展开
└─ 已加载内容 items(累计)
```

设计含义：

1. `page` 用于区分首屏加载与追加加载。
2. `loadingMore` 用于防止到底部时重复触发并发请求。
3. `hasMore` 用于在末页后及时停止继续加载。
4. `items(累计)` 用于保证下一页内容以追加方式呈现，而不是覆盖当前分类内容。

#### 筛选与分页协同

筛选与分页应遵循以下一致规则：

1. 切换筛选项后，分类态页码重置为 `page=1`。
2. 筛选区本身应保留，不应随着内容刷新一起销毁。
3. 筛选变化后，只刷新分类内容部分，不重建整个右侧内容骨架。
4. 筛选后的内容列表仍应支持滚动到底继续加载下一页。
5. 若筛选后结果为空，应保留筛选区并展示空态，而不是退回全页加载态。

#### 筛选区状态模型

分类筛选按钮也应明确区分三种状态：

```text
常态
  当前筛选值未生效，且没有焦点

聚焦态
  当前方向键停留在该筛选按钮上

选中态
  该筛选值已生效，但当前焦点可能已经离开
```

设计要求：

1. 筛选按钮应支持“已选中但当前未聚焦”的稳定表达。
2. 当方向键移动到已选中的筛选按钮上时，应优先呈现“选中 + 聚焦”的组合语义，而不是退化成单一状态。
3. 切换某个筛选值后，其他同组筛选值回到常态。
4. 筛选区整体展开或收起时，不改变已选中筛选值的语义。

#### 分类筛选刷新边界

为避免筛选操作导致整个右侧内容闪动，分类态应明确刷新边界：

1. 筛选值切换后，仅重置分类内容列表，不重建右侧模式容器。
2. 筛选行本身保留在原位置，不因刷新丢失焦点上下文。
3. 若当前筛选区处于展开状态，刷新后仍保持展开，除非用户主动收起。
4. 筛选切换触发的第一页加载，与滚动到底触发的追加加载，应在视觉和状态上明确区分。

### 2.1 搜索态

当左侧选中“搜索”时，右侧进入搜索态，而不是再打开一个全屏独立页面。

```text
左栏选中：搜索
  -> 右侧显示搜索面板
  -> 右移进入搜索面板
```

搜索态职责建议包括：

1. 承接关键词输入或最近搜索入口。
2. 展示热词或联想词等辅助信息。
3. 触发后续搜索结果浏览流程。

设计边界：

1. 本次不要求完整重做独立 `SearchActivity` 的全部视觉细节。
2. 首页右栏搜索态优先解决“同一骨架内承接搜索入口”的交互一致性问题。
3. 如需保留现有独立搜索页，应明确其作为兼容入口或深度搜索页的角色，避免与首页搜索态发生长期竞争。

### 2.2 收藏态

当左侧选中“收藏”时，右侧进入收藏态，而不是再打开一个全屏独立页面。

```text
左栏选中：收藏
  -> 右侧显示收藏内容列表
  -> 右移进入收藏内容
```

收藏态职责建议包括：

1. 以首页骨架内的方式展示当前收藏内容。
2. 允许在 TV 场景下快速进入收藏详情或播放。
3. 为后续删除、管理或跨配置切换预留空间。

设计边界：

1. 本次优先解决“收藏入口在首页右栏承接”的一致性问题。
2. 不要求同时完成独立收藏页的完整替代或下线。
3. 首页收藏态与独立收藏页若并存，需要在职责上清晰区分主入口与兼容入口。

### 3. 最近观看

最近观看在首页中应遵循以下规则：

1. 最多显示 4 条。
2. 不允许第一行在默认分辨率下超出屏幕宽度。
3. 在 4 条之后提供“更多历史”入口。
4. 最近观看优先服务“继续播放”而不是“完整历史浏览”。

### 4. 推荐内容带

四条推荐内容带建议使用统一的横向内容结构：

1. 高度保持一致
2. 单行横向滚动
3. 每条内容带标题语义稳定

这样可以避免五条内容带之间因卡片高度不一致而导致焦点体验割裂。

## 五、分类与推荐映射

### 当前现实约束

站点虽然会返回分类，但不同站点的命名并不统一，例如：

1. `剧集` / `电视剧` / `连续剧`
2. `动漫` / `动画`
3. `电影`
4. `综艺`

因此首页需要一层映射与回退策略，而不能假定所有站点都返回同名分类。

### 映射策略建议

建议引入三层优先级：

```text
首页标准分类
  -> 站点显式 categories 配置
    -> 站点返回 types 的名称匹配
      -> 找不到时回退为空或不展示该条内容带
```

### 回退原则

1. 某个标准分类无法映射时，不强行用错误分类顶替。
2. 首页固定内容带可按映射结果裁剪，但左侧原始站点分类仍可保留。
3. 右侧首页态中的推荐内容带以“准确优先”，避免误把综艺放进剧集栏。

## 六、焦点路径

### 总体原则

焦点移动必须让用户对“向左是导航，向右是内容，向上是状态，向下是浏览”形成稳定预期。

### 建议焦点模型

```text
顶部状态栏
  数据源名称 <-> 设置图标
                 ↓
左侧导航栏  <->  右侧内容区
```

### 具体规则

1. 默认进入首页时，首焦点建议落在左侧“首页”或右侧“最近观看第一项”之一，后续实现阶段二选一。
2. 从左侧导航右移，进入右侧当前内容带的首项。
3. 从右侧内容左移，回到当前左栏激活项。
4. 从右侧内容上移，在合适时回到顶部设置图标或数据源区域，但不应强制频繁跳顶。
5. 顶部状态栏的可聚焦元素数量应尽量少，避免与左侧导航抢焦点。
6. 从左栏选中搜索或收藏后右移，应直接进入对应右栏模式，而不是先要求额外确认。

### 分类态分页焦点规则

分类态在触发追加分页时，还应满足以下焦点约束：

1. 翻页成功后，焦点不应跳回顶部，也不应跳回左侧导航。
2. 当用户已移动到底部附近时，新增内容应自然接续当前浏览链路。
3. 追加加载期间，左侧导航仍保持当前项为激活态，而不是重新表现为聚焦主目标。
4. 从右侧最左列按左键返回时，仍回到当前激活的左栏分类项，不受已翻页页码影响。
5. 返回键从分类态回首页态时，不因为已经翻过多页而改变返回语义。

### 推荐的最小可聚焦集

为避免焦点碎片化，建议顶部仅保留两个可聚焦目标：

1. 数据源名称或数据源区域
2. 设置图标

网络图标和时间默认不加入焦点链。

## 七、更多历史承接

### 当前状态

当前项目中的 `HistoryDialog` 主要服务配置历史，不等同于观看历史浏览。

### 设计结论

首页中的“更多历史”不应直接等同于现有 `HistoryDialog`。

更合理的承接方向有两种：

#### 方案 A：独立历史页

优点：

1. 更适合 TV 浏览
2. 焦点和删除模式更清晰
3. 可与首页最近观看形成明确主次关系

#### 方案 B：新的观看历史弹窗

优点：

1. 成本较低
2. 保持轻量

缺点：

1. 对 TV 长列表体验一般
2. 删除、筛选、切换数据源的延展性较弱

当前更推荐方案 A，但本次设计阶段先只记录为待实现确认项。

## 八、分阶段落地建议

### 阶段 1：结构调整

1. 重建首页布局骨架
2. 拆出顶部状态栏、左侧导航栏、右侧内容区
3. 明确首页态与分类态切换模型

### 阶段 2：数据接线

1. 将站点分类接入左栏
2. 为首页四条推荐带建立分类映射策略
3. 限制最近观看数量并补充“更多历史”入口
4. 为分类态补齐分页状态与下一页追加策略
5. 明确筛选变化时的页码重置与内容保活边界
6. 为搜索态与收藏态定义右栏承接的数据来源与模式切换边界

### 阶段 3：焦点与状态

1. 调整顶部状态栏焦点规则
2. 接入设置图标与网络状态图标
3. 校验左右切换、上下跳转是否符合 TV 使用预期
4. 校验分类态追加分页过程中的焦点连续性
5. 校验左栏导航与筛选按钮的三态表达是否清晰可辨

## 九、风险与缓解

### 风险 1：五条内容带压缩过度

缓解：

1. 统一卡片高度
2. 限制最近观看数量
3. 让分类态与首页态分离，避免右侧同时承担过多任务

### 风险 2：分类映射误判

缓解：

1. 优先使用站点显式分类配置
2. 名称匹配失败时宁可不展示该推荐带
3. 保留左侧原始分类入口作为能力回退

### 风险 3：顶部焦点过碎

缓解：

1. 顶部只保留最少可聚焦元素
2. 网络图标和时间默认只展示状态
3. 避免把状态栏做成多个并列按钮区

### 风险 4：分类态重复请求或分页状态错乱

缓解：

1. 追加加载时维护独立的 `loadingMore` 状态，避免到底部重复触发。
2. 以 `pageCount` 与空列表结果共同约束 `hasMore`，避免末页死循环。
3. 筛选变更时显式重置页码和累计内容，避免旧页数据串入新筛选结果。
4. 尽量复用现有 `TypeFragment` / `CustomScroller` 的成熟分页语义，降低首页重构带来的行为分叉。

### 风险 5：搜索态、收藏态与现有独立页面职责重叠

缓解：

1. 首页右栏搜索态、收藏态优先解决入口承接一致性，不强行一次性替代所有独立页面能力。
2. 若保留独立页面，应明确其为兼容入口、深度管理入口或迁移过渡入口。
3. 后续如决定彻底统一入口，再通过单独变更收敛旧页面职责，避免本次首页重构目标失控。

### 风险 6：导航态与筛选态表达不清

缓解：

1. 左栏导航和分类筛选都明确区分常态、聚焦态、激活/选中态。
2. 避免把聚焦态和激活态画成完全相同的视觉。
3. 在设计与验证阶段加入离焦后的状态检查，确保“当前内容归属”和“当前焦点位置”都能被用户一眼识别。
